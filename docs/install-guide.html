🪟 Windows インストール手順

Docker Desktop for Windows がインストール済みの前提です。PowerShell 5.1 以上で実行します。
🐳
Docker Desktop 4.x+
WSL2 backend 推奨 — ダウンロード ↗
💻
PowerShell 5.1+
Windows 10/11 標準搭載
💾
ディスク空き容量
6 GB 以上推奨
🌐
インターネット接続
Docker イメージ取得に必要
1
Docker Desktop を起動する
スタートメニューから Docker Desktop を起動し、タスクトレイのクジラアイコンが「Running」になるまで待ちます。
powershell
# Docker が起動しているか確認
docker info
ℹ️ WSL2 バックエンド推奨: Docker Desktop の Settings → General → "Use the WSL 2 based engine" を有効にすると I/O 性能が向上します。
2
リポジトリを配置する
iotpf-proto ディレクトリをダウンロードまたは git clone で取得し、プロジェクトルートに移動します。
powershell
# git clone する場合
git clone https://github.com/taz-szk/iotpf-proto.git
cd iotpf-proto

# または ZIP 展開後に移動
cd C:\Users\YourName\iotpf-proto
3
インストーラーを実行する
プロジェクトルートで install-windows.ps1 を実行します。シークレットを自動生成し、Docker イメージのプルと全サービスの起動を行います。
⚠️ 実行ポリシー: スクリプトが実行できない場合は下記コマンドで一時的に許可します。
powershell
# 実行ポリシーを一時的に変更（現在のプロセスのみ）
Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope Process

# インストーラー実行
.\install-windows.ps1
⚠️ シークレットを保存してください: スクリプト実行時に表示されるパスワード類を安全な場所（パスワードマネージャー等）に記録します。.env ファイルにも同じ値が保存されますが、Git にはコミットしないでください。
4
動作確認する
全コンテナが healthy になったら、以下のURLにアクセスして動作を確認します。
URLサービス認証情報
http://localhost:8000/docsCore API (Swagger UI)JWT トークン（ログイン後）
http://localhost:3000Grafanaadmin / .env の GRAFANA_ADMIN_PASSWORD
http://localhost:18083EMQX Dashboardadmin / .env の EMQX_DASHBOARD_PASSWORD
http://localhost:9001MinIO Consoleminioadmin / .env の MINIO_ROOT_PASSWORD
http://localhost:8025MailHog (メール確認)認証不要
http://localhost:8086InfluxDB UIadmin / .env の INFLUXDB_ADMIN_PASSWORD
powershell — コンテナ状態確認
docker compose ps
5
よく使うコマンド
powershell
# 停止
docker compose down

# 再起動
docker compose up -d

# ログ確認（全サービス）
docker compose logs -f

# 特定サービスのログ
docker compose logs -f core-api

# データを完全削除して再構築
docker compose down -v
.\install-windows.ps1
6
実行ログ例（正常完了時）

🍎 macOS インストール手順

Docker Desktop for Mac がインストール済みの前提です。bash / zsh シェルで実行します。
🐳
Docker Desktop 4.x+
Apple Silicon (M1/M2/M3) 対応版 — ダウンロード ↗
🔐
openssl
macOS 標準搭載 / brew install openssl
💾
ディスク空き容量
6 GB 以上推奨
1
Docker Desktop を起動する
Applications から Docker.app を起動し、メニューバーのクジラアイコンが「Docker Desktop is running」になるまで待ちます。
bash
# Docker が起動しているか確認

🐧 Ubuntu インストール手順

Docker Desktop for Linux がインストール済みの前提です。Ubuntu 22.04 LTS / 24.04 LTS で動作確認済みです。
🐳
Docker Desktop 4.x+
deb パッケージでインストール — ダウンロード ↗
🔐
openssl
apt でインストール可（スクリプトが自動対応）
💾
ディスク空き容量
6 GB 以上推奨
1
Docker Desktop をインストール・起動する
Docker Desktop for Linux の .deb パッケージを Docker 公式サイトから取得してインストールします。
bash — インストール済みの場合は起動のみ
# Docker Desktop 起動（systemd ユーザーサービス）
systemctl --user start docker-desktop

# または Applications メニューから Docker Desktop を起動

# 起動確認
docker info
ℹ️ Docker Engine (CLI のみ) を使う場合: Docker Desktop ではなく docker-ce + docker-compose-plugin をインストールしても動作します。その場合 sudo が必要になることがあります。
2
リポジトリを配置する
bash
git clone https://github.com/taz-szk/iotpf-proto.git
cd iotpf-proto
3
インストーラーを実行する
実行権限を付与してインストーラーを起動します。openssl が未インストールの場合は apt install openssl を自動実行します（sudo パスワードの入力を求められます）。
bash
chmod +x install-ubuntu.sh
./install-ubuntu.sh
⚠️ .env のパーミッション: Ubuntu 版スクリプトは生成した .env に chmod 600 を適用します（所有者のみ読み取り可能）。
⚠️ シークレットを保存してください: 表示されるパスワード類をパスワードマネージャーに記録します。
4
ファイアウォールの設定（UFW）
UFW が有効な環境では、MQTT ポートへの外部アクセスを許可します（ローカル開発環境では不要）。
bash — 本番/外部公開環境のみ
# MQTT over TLS
sudo ufw allow 8883/tcp

# HTTPS (nginx)
sudo ufw allow 443/tcp
sudo ufw allow 80/tcp

# 開発環境（localhost アクセスのみ）の場合は UFW 設定不要
5
動作確認する
URLサービス認証情報
http://localhost:8000/docsCore API (Swagger UI)JWT トークン（ログイン後）
http://localhost:3000Grafanaadmin / .env の GRAFANA_ADMIN_PASSWORD
http://localhost:18083EMQX Dashboardadmin / .env の EMQX_DASHBOARD_PASSWORD
http://localhost:9001MinIO Consoleminioadmin / .env の MINIO_ROOT_PASSWORD
http://localhost:8025MailHog認証不要
http://localhost:8086InfluxDB UIadmin / .env の INFLUXDB_ADMIN_PASSWORD
bash — コンテナ状態確認
docker compose ps
✅ 全コンテナが healthy になればセットアップ完了です。
6
よく使うコマンド
bash
# 停止
docker compose down

# 再起動
docker compose up -d

# ログ確認
docker compose logs -f core-api

# 起動時に自動起動する設定

# データを完全削除して再構築
docker compose down -v
./install-ubuntu.sh

🤖 AIアシスタントの初期セットアップ

AIアシスタント（ローカルLLMによるドキュメントQ&A・操作代行）は選択制の機能です。 Ollama（3B級モデル）の実行には2GB以上のメモリが必要なため、メインの環境とは別インスタンスで Ollamaを動かすことを強く推奨します（小規模インスタンスに同居させるとメモリ不足で 不安定になります）。OS共通の手順で、プロジェクトルートで実行します。
1
インストーラでAIアシスタントを有効にする（未実施の場合）
install-mac.sh・install-ubuntu.sh・install-aws.sh・ install-windows.ps1の初回実行時に「AIアシスタント機能を将来使う予定はありますか？」 と聞かれ、yと答えると.envのPOSTGRES_IMAGEが pgvector/pgvector:pg16に設定されます。既に.envを生成済みで 後から有効にしたい場合は、手動で編集してください。
bash
# .envに以下の行を追加/変更
POSTGRES_IMAGE=pgvector/pgvector:pg16

# 反映
docker compose up -d --force-recreate postgres
✅ 既存ボリュームはそのまま使えます。 pgvector/pgvector:pg16は同じPostgreSQL 16系のため、既存の postgres_dataボリュームと互換です。データ移行やダンプ・リストアは不要ですが、 alpine→debianのlibc差異によるコレーション互換性のため、切替後に一度 REINDEX DATABASEを実行することを推奨します。
2
Ollama用インスタンスを用意する
メインの環境とは別のマシン/インスタンスにOllamaを立てます。同一VPC/ネットワーク内であれば プライベートIPで通信でき、公開する必要はありません。ローカル開発で同居させたいだけの場合は docker-compose.ollama.ymlを使う簡易手順（本ステップの末尾）もあります。
bash
# Ollama専用インスタンス上で実行
curl -fsSL https://get.docker.com | sudo sh
docker run -d --name ollama -p 11434:11434 \
  -v ollama_data:/root/.ollama --restart unless-stopped \
  ollama/ollama:latest

docker exec ollama ollama pull qwen2.5:3b
docker exec ollama ollama pull nomic-embed-text
docker exec ollama ollama list
⚠️ セキュリティグループ/ファイアウォールで11434番ポートを メインインスタンスからのみ許可してください。Ollamaには認証機構が無いため、 広く公開すると誰でも推論を実行できてしまいます。
💡 ローカル開発で同居させたい場合は、専用インスタンスの 代わりに同一マシンでdocker compose -f docker-compose.yml -f docker-compose.ollama.yml up -d を実行し、接続先URLはhttp://ollama:11434を使ってください（次ステップ）。
3
プラットフォーム設定画面でOllama接続先を設定する
プラットフォーム管理コンソール（/iotairx-console/）の設定画面「AIアシスタント接続設定」で、 手順2で用意したOllamaの接続先URL（例: http://172.31.19.73:11434）を入力し、 「接続テスト」で疎通を確認してから保存します。この設定を保存するまでAIアシスタント機能は 非表示のままで、テナント画面にも影響しません。
4
ドキュメントを再インデックスする
同じ設定画面の「ドキュメント再インデックス」を実行します。 docs/ 配下のドキュメントと CLAUDE.md が読み込まれ、 チャンクごとにベクトル化されて PostgreSQL に保存されます。
項目内容
/iotairx-console/プラットフォーム管理コンソール → 設定 → AIアシスタント
POST /platform/assistant/reindex再インデックスAPI（管理コンソールのボタンから呼ばれます）
⚠️ チャンク件数が 0 件でないことを必ず確認してください。 0 件の場合は core-api コンテナに docs/ と CLAUDE.md がマウントされていません （docker-compose.yml の core-api の volumes に ./docs:/docs:ro と ./CLAUDE.md:/CLAUDE.md:ro が必要）。 対象ファイルが 1 件も見つからない場合、API は既存インデックスを消さずに 500 エラーを返します。
💡 ドキュメントを更新したときは、再度この再インデックスを実行してください。 インデックスは実行時点のファイル内容のスナップショットです。

⬆️ 既存環境をv2.0.1にアップグレードする手順

v2.0.0以前の環境で、AIアシスタント機能をOllama同梱・環境変数ベースの旧構成で 先行導入していた場合の移行手順です。新規インストールの場合は上記「AIアシスタントの初期セットアップ」 をそのまま実施すればよく、本セクションは不要です。
1
サーバー上の手動編集をリセットしてpullする
旧構成のトラブルシューティングでdocker-compose.yml・nginx/conf.d/api.conf・ core-api/app/services/ollama_client.pyを直接編集していた場合、そのままでは git pullが競合します。新しいリポジトリ版がこれらを正しく置き換えるため、 手動編集は破棄して問題ありません。
bash
cd ~/iotpf-proto
git status
git checkout -- docker-compose.yml nginx/conf.d/api.conf core-api/app/services/ollama_client.py
git pull origin main
2
.envにPOSTGRES_IMAGEを追加する
新しいdocker-compose.ymlは${POSTGRES_IMAGE:-postgres:16-alpine}という 書き方に変わっている。.envはgit管理外のため自動更新されない。
⚠️ これを忘れると次のdocker compose up -dで postgresイメージが意図せずpostgres:16-alpine（pgvector非対応）に巻き戻ります。 既にpgvector運用中の環境では必ず先に設定してください。
bash
echo "POSTGRES_IMAGE=pgvector/pgvector:pg16" >> .env
grep POSTGRES_IMAGE .env
3
反映する
bash
docker compose up -d
docker compose up -d --build core-api
docker compose ps postgres   # イメージがpgvector/pgvector:pg16のままか確認
4
Ollama接続先をプラットフォーム設定画面で再設定する
旧構成のOLLAMA_URL等の環境変数は廃止された。プラットフォーム管理コンソール （/iotairx-console/）の設定画面「AIアシスタント接続設定」で、Ollama専用インスタンスの 接続先URL・チャットモデル・埋め込みモデルを入力し、「接続テスト」で疎通確認後に保存する。 保存するまでAIアシスタントタブは非表示のまま。
