# デバイス位置情報(GPS)表示機能 設計スペック

## 意図・背景

テナント内のデバイスが、全世界に散らばって動く場合（配送車両など）と、工場・拠点に集約されている場合の両方があり得る。現状、デバイスの位置情報を表示する手段が無い。

Grafanaの地図パネル(Geomap)への組み込みはInfluxDBデータの受け渡しが煩雑になりがちなため、テナントポータル内に独立した位置情報モジュールとして作る。

## ゴール

- テナント内の全デバイスの最新位置を1枚の地図上にピン表示する「全体表示」画面
- ピンをクリックすると、その1台の移動履歴(軌跡)を期間指定で表示する「履歴」画面に遷移する
- 地図の初期表示位置・初期ズームを、テナントごとに保存・変更できる(「この表示をデフォルトにする」ボタン)
- 動作確認用に、シミュレータが移動ルートをシミュレートして送信できる

## 非ゴール・アンチゴール

- Grafanaダッシュボードへの地図パネル組み込み(今回は見送り)
- ジオフェンシングなどのアラート機能との連携(将来の拡張候補、今回はスコープ外)
- 地図タイルの自前ホスティング(全世界をカバーするのは非現実的)
- 手入力で緯度経度・ズームを数値指定するUI(「現在の表示を保存」ボタンで十分とする)

## 決定した設計

### データの送り方(デバイス→バックエンド)

既存のテレメトリの仕組みに乗せる。デバイスは`latitude`・`longitude`という名前のセンサー値を、既存のMQTT経由のテレメトリ送信にそのまま含めて送る。ingestion-service・InfluxDBの保存経路は変更不要（既存のセンサーキーと同じ型・同じ保存先）。

### テナントポータルUI

`admin-ui/tenant-portal.html`に新規タブ「位置情報」を追加する。編集操作を伴わない閲覧機能なので、全ロール(admin/operator/viewer)が閲覧可能とする(**既存の「デバイス」タブ等と同じ閲覧権限の考え方**)。

**全体表示画面**
- テナント内の全デバイスの最新の`latitude`/`longitude`を取得し、OpenStreetMapの地図上にピン表示する
- **位置の鮮度**: 最新の位置情報が1時間より古い（＝直近1時間、通信が無い）デバイスは「位置不明」として扱う。地図上にはピンを出さず、デバイス一覧側にも「位置不明」等の表示をする。配送車両等を想定すると、古い位置をそのまま表示し続けると誤解を招くため
- **デバイスグループによる絞り込み**: 既存のデバイスグループ機能(`device_groups`)を使い、全体表示をグループ単位で絞り込めるようにする。UIはグループ選択のドロップダウンを画面上部に置く(既存のアラートルール画面のグループ選択と同様の見た目)。「全て」を選べばグループなしの全件表示
- 地図の初期中心・初期ズームは、テナントごとに保存された値を使う(未設定なら実装側で決める適当な既定値、例: 日本全体が入る程度)
- 「この表示をデフォルトにする」ボタン(admin/operatorのみ、既存の`canEdit`相当の権限)。押した時点の地図の中心・ズームを保存する
- ピンをクリックすると履歴画面に遷移する

**履歴画面**
- 1台のデバイスの`latitude`/`longitude`の時系列データを、期間を指定して取得し、地図上に線(軌跡)で表示する
- 期間指定のUIは既存のダッシュボード・統計画面の期間選択パターンに合わせる(**ビルダーの判断に委ねる**: 具体的なプリセット・UIコンポーネント)
- **期間の上限**: 1回のクエリで取得できる期間は最大7日間とする(5秒間隔送信・30日分だと約50万点になり、API応答・Leafletの描画の両方が破綻するため)。期間選択UIも7日を超える範囲を選べないようにする

### 地図描画ライブラリ

Leaflet.js（軽量・OpenStreetMapタイル前提の定番ライブラリ）を静的ファイルとしてローカルに配置し、既存のTailwind/Alpine/QRCodeと同様にCDN経由にしない。

**ただし地図タイル画像そのものは例外的に外部(デフォルトはOpenStreetMapのタイルサーバー)から読み込む。** これまでの「外部CDN不使用」方針からの明示的な例外（ユーザー承認済み）。OSMの標準タイルはズームレベル18〜19程度(建物単位)まで無料で利用でき、GNSS相当の精度での表示に十分だが、利用規約上、重い商用利用には適さない（帰属表示も必須）。

**タイルURLは設定値にする**（将来、有料のタイルプロバイダ(MapTilerなど)に切り替えられるようにするため）。`core-api/app/config.py`に`map_tile_url_template: str`（既定値はOSMの標準タイルURL `https://tile.openstreetmap.org/{z}/{x}/{y}.png`）・`map_tile_attribution: str`（既定値はOSMの帰属表示文）を追加し、既存の`RECAPTCHA_SITE_KEY`等と同じ`.env`経由の設定として扱う。フロントエンドは`GET /tenant-portal/me`等、既存の設定取得APIの応答にこの2値を含めて渡す（具体的にどのエンドポイントに含めるかは**ビルダーの判断に委ねる**）。

タイルプロバイダの切り替えに伴い、CSPの`img-src`に許可するホストも変わりうる。今回はOSMの標準タイルホスト(`tile.openstreetmap.org`。サブドメイン分散は使わない現行の推奨URLに合わせる)を`img-src`に追加する。Leaflet.js自体はローカル配置のため`script-src`の変更は不要。将来別のタイルプロバイダに切り替える場合は、このCSPも合わせて更新が必要になる(自動化はしない)。

### データモデル(新規)

`core-api/app/models/public.py`に、テナントごとの地図デフォルト表示設定を追加する。`Tenant`テーブルに直接カラムを追加する(既存の`bill_shock_threshold_amount`等と同じ、テナント単位設定カラムを増やすパターン):

```python
# Tenant クラスに追加
map_default_lat = Column(Float, nullable=True)
map_default_lng = Column(Float, nullable=True)
map_default_zoom = Column(Integer, nullable=True)
```

`core-api/app/database.py`に`migrate_add_map_default_view()`を追加し、既存の`migrate_*`と同じ`ADD COLUMN IF NOT EXISTS`パターンで`app/main.py`の起動時マイグレーションタプルに登録する。

### バックエンドAPI(新規、`tenant_portal.py`に追加)

- `GET /tenant-portal/me/device-locations?group_id=...`(`group_id`省略可。指定時はそのグループのデバイスのみ) — 各デバイスの最新`latitude`/`longitude`と受信時刻を返す。受信時刻が1時間より古いデバイスは、位置不明として(ピン非表示用に)フラグを立てて返す(除外するのではなく、一覧表示側で「位置不明」と出せるようにする)
- `GET /tenant-portal/me/devices/{device_id}/location-history?start=...&end=...` — 指定デバイス・期間の`latitude`/`longitude`の時系列を返す。`end - start`が7日を超える場合は422(既存の`validate_retention_days`等と同様、リクエストバリデーションとしてエラーにする)
- `PUT /tenant-portal/me/map-default-view` — `{lat, lng, zoom}`を受け取り`Tenant`のカラムを更新(admin/operatorのみ)

具体的なInfluxDB/Fluxクエリの実装（既存のセンサー値取得パターンのどれを再利用するか）は**ビルダーの判断に委ねる**。

### シミュレータの変更

`simulator/`に移動ルートのシミュレーション機能を追加する。シミュレータのGUIは設定保存のたびに`config.json`を丸ごと上書きする仕組みのため、GPS関連の設定もGUI側に入力欄を追加する(直接`config.json`を手編集しても保存時に消えてしまうため)。

- GUIに「GPS移動シミュレーション」のセクションを追加: 有効/無効のチェックボックス、基準となる緯度経度(`base_lat`/`base_lon`)の入力欄
- 複数デバイスを同時に動かす場合、全端末が同じ基準点から出発すると地図上でピンが重なり「全体表示」の動作確認にならない。**各デバイス(ワーカー)は起動時に基準点から小さくランダムなオフセットを一度だけ割り当て**、そこを中心に移動させる(デバイスごとに別々の基準点を手入力させるのではなく、1つの基準点から自動的に散らす)
- 有効時、一定間隔ごとに小さくランダムに位置がずれた`latitude`/`longitude`を、既存のテレメトリ送信と同じタイミングで送る(簡易なランダムウォーク。経路の事前定義などは行わない)。既存の`device_worker.py`のテレメトリ生成ロジックに追加する形になる想定（**ビルダーの判断に委ねる**: 具体的な移動幅・頻度の数値）
- GUIでの項目追加に伴い、Windows向けexeの再ビルドが必要。リリースパッケージへの再添付も忘れないこと([[feedback_release_attach_simulator_exe]]参照)

## ビルダーに委ねる部分

- 履歴画面の期間選択UIの具体的なプリセット・コンポーネント(7日上限の範囲内)
- 位置情報を持たない・位置不明なデバイスの一覧上の具体的な表示文言
- 地図のデフォルト値(保存されていない場合の初期中心・ズーム)
- InfluxDB/Fluxクエリの具体的な実装
- シミュレータのランダムウォークの移動幅・送信頻度の数値、各ワーカーへのオフセット割り当ての具体的な範囲
- `map_default_lat`/`lng`/`zoom`のバリデーション範囲(緯度-90〜90等)
- 「位置不明」判定の1時間という閾値を将来設定可能にするかどうか(今回はハードコードでよい)
