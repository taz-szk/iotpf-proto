# IoTAir-X プロモーションページ刷新 要件定義書

- 対象ページ: https://iot.suzuki-net.org/docs/promo.html
- 参照設計書: https://iot.suzuki-net.org/docs/design.html
- 作成日: 2026-10-04

## 1. 概要・目的

現行の `promo.html` は静的HTML（JSライブラリ未使用）で、マルチテナント型IoTデバイス管理基盤「IoTAir-X」の機能を紹介している。しかし掲載内容が設計書（design.html）の最新機能に追従していない（例: 多要素認証(MFA)設定、RAGアシスタント設定、SIM管理、グループ管理などが手薄）。

本刷新の目的は、**展示会・デモブースでの訴求力向上**を目的に、design.html記載の最新機能を反映しつつ、アニメーションによって視覚的にわかりやすく伝えるページへリニューアルすること。

## 2. 想定利用シーン・トーン

- **利用シーン**: 展示会・デモブースでの常設表示（来場者がブース内のPC/ディスプレイで閲覧。自動再生、またはワンタッチでのスクロール閲覧を想定）
- **トーン**: ビジュアル訴求重視。テキスト量は少なめ、図・アイコン・数値・アニメーションで直感的に機能を伝える
- **CTA**: 最小限（問い合わせ先・ブース担当者への誘導程度）。商談化を強く迫るCTAは不要
- **操作性**: 来場者が操作しなくても内容が伝わること（スクロール or 自動タイムラインでの進行を想定）

## 3. 情報構成（章立て）

既存 `promo.html` の7セクション構成を土台に、design.html の内容へ刷新する。

### 3.1 ヘッダー
- 製品名「IoTAir-X」、タグライン
- 主要機能タグ（MQTT mTLS / リアルタイムダッシュボード / OTA配信 / アラート通知 / 利用量課金 / MFA / RAGアシスタント）

### 3.2 システム構成（アーキテクチャ概要）
design.html「I. システムアーキテクチャ概要」を元に構成。

- 全体構成: マルチテナント型IoTデバイス管理基盤。テナントデータの論理・物理分離
- 主要コンポーネント（図示対象）:
  - nginx（TLS終端・リバースプロキシ）
  - core-api（FastAPI :8000）
  - ingestion-service（FastAPI :8001）
  - alert-service（Python）
  - EMQX 5.x（MQTTブローカー、mTLS :8883）
  - PostgreSQL 16
  - InfluxDB 2.x
  - Grafana OSS（SSO統合ダッシュボード）
  - MinIO（ファームウェアストレージ）
  - Step-CA（デバイス証明書PKI）
- ネットワーク分離: external / internal / grafana-net の3層構成

### 3.3 テナント管理者機能
design.html「II. テナント管理者機能」を元に構成。エンドユーザ（テナント側）が実際にできることを先に示す。

| 機能 | 掲載内容 |
|---|---|
| ブートストラップトークン管理 | 複数トークン発行、最大デバイス台数・有効期限設定、ステータス管理（active/expired/depleted） |
| デバイス管理 | トークン認証→Step-CA証明書発行→デバイス登録のプロビジョニングフロー、EMQX Webhookによる接続状態管理 |
| OTAファームウェア更新 | MinIO格納（最大100MB）、署名付きJWT（24時間有効）によるセキュアな配信、パストラバーサル対策 |
| SIM(SORACOM)管理 | 回線一覧・状態変更（有効化/停止/利用中断等）、速度クラス変更、デバイス紐づけ |
| グループ管理 | 拠点・機種単位のグループ化、アラートルール・OTA配信・ダッシュボード表示のグループ単位統制 |
| ビリング管理 | 課金項目8種（基本料金・データポイント数・保持データ・デバイス台数等）の確認、請求書ライフサイクル確認 |
| 統計・ダッシュボード（内部） | Grafana SSO統合、Auth Proxy保護、テナントごとのGrafana org分離、グループ連動変数によるフィルタリング |
| 統計・ダッシュボード（公開） | テナント統計API（`/me/stats`）による概要表示 |

### 3.4 PF管理者機能
design.html「III. プラットフォーム管理者機能」を元に構成。テナント管理者機能を陰で支える、ミドルB（プラットフォーム運営者）側の管理機能として位置づける。

| 機能 | 掲載内容 |
|---|---|
| テナント管理 | テナント作成時のPostgreSQLスキーマ・InfluxDB org・Grafana org自動プロビジョニング、ステータス管理（active/suspended/deleted） |
| 料金テーブル設定 | テナント単位の単価マスタ設定、スナップショット設計（請求書に計算時点の単価を保持し将来の単価変更が過去請求に影響しない） |
| 請求・統計処理 | 日次バッチによるdraft→finalized遷移、修正(corrected)ワークフロー、全テナント統計閲覧 |
| 多要素認証(MFA)設定 | TOTP（RFC 6238準拠）、platform_required/tenant_requiredのON/OFF切替、紛失時リセット対応 |
| RAGアシスタント設定 | ローカルLLM（Ollama: qwen2.5:3b / nomic-embed-text）、pgvectorによるベクトル検索、ドキュメント再インデックス、操作代行ツール（確認フロー付き：トークン発行・パネル設定・アラートルール作成） |

### 3.5 統合機能
- SORACOM連携（SIM管理の裏側にあるキャリア連携）
- RAGアシスタントによる操作代行（チャットでの問い合わせ→確認→実行フロー）

### 3.6 まとめ
- 全機能一覧（箇条書きで網羅的に再掲、design.html掲載の全FR項番を参照できる形に）

### 3.7 技術スタック
- FastAPI、PostgreSQL 16、InfluxDB 2、EMQX 5、Grafana、MinIO、Step-CA、nginx、Docker Compose
- （刷新により追加されたもの）Ollama、pgvector

## 4. アニメーション要件

実装は**軽量CSSアニメーションのみ**（追加JSライブラリ不要、既存の静的HTML方針を維持）。

| セクション | アニメーション方針 |
|---|---|
| ヘッダー | フェードイン＋タグラインのタイプライター風（CSSのみ、`steps()`アニメーション） |
| システム構成 | 構成図のコンポーネントを順番にフェードイン、データフローの矢印・ラインをCSSの`stroke-dashoffset`等で描画風に表現 |
| テナント管理者機能 | 各機能カードをスクロール連動でスライドイン（`@keyframes` + `animation-timeline`またはIntersection Observer不要の軽量実装を検討）。機能数が多いため、グリッド表示＋ホバー/自動ハイライトの切替アニメーション |
| PF管理者機能 | 同上の演出パターンを継承。テナント管理者機能を支える位置づけが視覚的に伝わるよう、1段落ち着いたトーンで表示 |
| 統合機能 | チャット→確認→実行のフローをステップ送りアニメーションで表現 |
| まとめ | 数値（対応FR数、コンポーネント数等）のカウントアップ表現 |
| 技術スタック | ロゴ/バッジが順番にフェードイン |

- 自動再生を前提とする場合、無限ループまたは一定時間後に先頭セクションへ戻る設計を検討
- `prefers-reduced-motion` への配慮（アクセシビリティ上の最低限の対応）

## 5. 非機能要件

- レスポンシブ対応（展示会ディスプレイの大画面〜ノートPC閲覧を想定）
- 主要ブラウザ（Chrome / Edge / Safari）で表示崩れがないこと
- 追加JSライブラリ非依存（軽量・保守容易性を優先）
- 自動再生時にループ再生、または一時停止操作ができること

## 6. コンテンツソース

各セクションの文言・数値・機能説明は本書 3章に記載の対応関係に従い、design.htmlの該当章（I〜III章）を正とする。本書作成時点のdesign.html記載内容を基準とし、実装時に差分があれば最新のdesign.htmlを確認する。

## 7. スコープ外

- 本書は要件定義のみであり、実際のHTML/CSS実装は別タスクとする
- バックエンドAPI・design.html自体の変更は対象外
- 多言語対応（英語版等）は本刷新のスコープ外
