Device Simulator

IoT デバイスシミュレータ
利用ガイド

クロスプラットフォーム GUI アプリ（Tkinter・Windows / macOS 対応）で仮想デバイスを動かし、テレメトリ送信・OTA 更新・異常値注入をテストできます。

01起動方法

1
依存ライブラリをインストールする
shell
cd simulator
pip install -r requirements.txt
ℹ️ Tkinter は Python 標準ライブラリに含まれています。SDK (iot-platform-sdk) が Python 3.11 以上を要求するため、Python 3.11 以上が必要です。
macOS で Homebrew Python を使う場合: Tkinter が別パッケージになっているため brew install python-tk@3.x（例: python-tk@3.12）を追加でインストールしてください。python.org からインストールした Python はそのまま使えます。
2
シミュレータを起動する
shell
python simulator.py

前回の設定（テナント・デバイス・テレメトリ設定）は config.json から自動で復元されます。

03基本的な使い方

① テナントを追加する

「+ 追加」ボタンでテナント設定ダイアログを開き、以下を入力します。

項目説明例
テナント名 *識別用の任意名称My Tenant
API URLcore-api のベース URLhttps://localhost/api
MQTT ホストEMQX ブローカーのホストlocalhost
MQTT ポートTLS ポート（デフォルト 8883）8883
Bootstrap Tokenプロビジョニングトークン（管理画面から発行）bsp_xxxxxxxxxxxx
管理者メールデバイス削除時に使用（任意）admin@example.com
管理者パスワードデバイス削除時に使用（任意）—
SSL 証明書を検証するオフにすると自己署名証明書を許可ローカル環境ではオフ推奨

② デバイスを追加する

デバイス一覧の「+ 追加」ボタンを押し、Device ID とテナントを選択して OK します。

デバイスは自動でプロビジョニングを開始します（Bootstrap Token → mTLS 証明書取得 → MQTT 接続）。

状態表示意味
⚡ provisioning橙証明書取得中。初回のみ発生。
⟳ connecting青MQTT ブローカーへの接続中。
● connected緑接続済み。テレメトリ送信可能。
○ disconnected灰切断中。「接続」ボタンで再接続可。
✗ error赤接続エラー。ログで詳細を確認。
ℹ️ 証明書はローカルにキャッシュされます。 一度プロビジョニングした証明書は simulator/certs/<テナント名>/<device_id>/ に保存され、次回起動時は再取得しません。

③ テレメトリを送信する

接続済みのデバイスに向けて「▶ 送信開始」を押すと、設定した間隔でテレメトリを一斉送信します。

✅ 送信データは Grafana ダッシュボードでリアルタイムに確認できます（http://localhost:3000）。

04テレメトリ設定

ランダム値モード

各フィールドに min〜max の範囲でランダムな値を生成します。「異常値」と「確率(%)」を設定すると、指定確率で異常値に差し替えてアラートテストができます。

列説明
フィールド名センサーキー名（例: temperature、humidity）
最小値 / 最大値正常時の乱数範囲
異常値異常時に送る固定値（例: 100.0）
確率(%)異常値を送る確率（例: 1.0 = 1%）
💡 アラートルールのテスト方法: 異常値の確率を 100% にして「▶ 送信開始」すれば、すぐにアラート条件を満たすデータを連続送信できます。

カスタム JSON モード

テキストエリアに任意の JSON を入力すると、その内容を毎回固定値として送信します。動的な値は使えませんが、特定のペイロード構造をテストしたい場合に便利です。

json — カスタム JSON の例
{
  "temperature": 42.5,
  "motor_rpm": 3200,
  "error_code": 5
}

05OTA 更新シミュレーション

管理画面から OTA コマンドを送信すると、シミュレータが自動で受信・処理します。手動操作は不要です。

1
管理画面でファームウェアをアップロードする
Core API の POST /tenants/{id}/firmware でファームウェアファイル（任意バイナリ）をアップロードします。
2
OTA コマンドを送信する
対象デバイスに POST /tenants/{id}/devices/{did}/ota を実行します。EMQX 経由でデバイスに OTA コマンドが届きます。
3
シミュレータが自動でダウンロード・検証する
OTA 進捗ウィンドウが自動で開き、ダウンロード → SHA256 検証 → バージョン更新の過程を表示します。
✅ チェックサム一致でバージョンが更新され、デバイス一覧の fw: x.x.x 表示が変わります。
⚠️ チェックサム不一致の場合は OTA 失敗としてエラー表示します。ファームウェアファイルの整合性テストに使えます。

06その他の操作

デバイスの切断 / 再接続

デバイス行右端の「切断」/「接続」ボタンで手動でブローカーとの接続を制御できます。オフライン → online の切り替わりを Grafana で確認するテストに使います。

デバイスの削除

デバイス行の ✕ ボタンで削除します。以下の3つを同時に実行します:

  • シミュレータからデバイス除外
  • プラットフォーム側 API でデバイス登録を削除（管理者メール/パスワードが設定されている場合）
  • ローカルの mTLS 証明書ディレクトリを削除
⚠️ 削除したデバイスを再度追加すると Bootstrap Token で再プロビジョニングし、新しい証明書が発行されます。

複数デバイスの一括操作

「▶ 全開始」「■ 全停止」ボタンで全デバイスへのテレメトリ送信を一括制御できます。

設定の保存

ウィンドウを閉じると設定（テナント・デバイス・テレメトリ設定）が simulator/config.json に自動保存されます。次回起動時に自動復元されます。

スタンドアロン EXE のビルド Windows 版のみ

Python 環境なしで動作する単体 EXE（約 38 MB）を PyInstaller でビルドできます。

1
simulator/ ディレクトリへ移動する
powershell
cd simulator
2
スクリプト実行ポリシーを設定する（初回のみ）
powershell
Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope Process
3
ビルドスクリプトを実行する
powershell
./build
依存パッケージのインストール（pip）と PyInstaller によるバンドルが自動で実行されます。初回は数分かかります。
4
生成された EXE を配布する
ビルド完了後、simulator/dist/IoT_Simulator.exe が生成されます。この 1 ファイルをそのまま配布できます。
ℹ️ certs/ ディレクトリと config.json は EXE と同じ場所に初回起動時に自動生成されます。Python のインストールは不要です。

07トラブルシューティング

症状原因・対処
⚡ provisioning のまま変わらないBootstrap Token が無効か期限切れ。管理画面で有効なトークンを確認。上限デバイス台数に達していないかも確認。
✗ error になるMQTT ブローカーに接続できない。プラットフォームが起動しているか、ホスト・ポートが正しいか確認。
SSL エラーが出る自己署名証明書の環境では「SSL 証明書を検証する」をオフにする。
テレメトリが Grafana に出ないデバイスが connected 状態か確認。ingestion-service のログを確認（docker compose logs ingestion-service）。
OTA が始まらないデバイスが connected 状態であることが必要。EMQX の Webhook ルールが有効か確認。
config.json の読み込みエラーファイルを削除して再起動すると初期状態に戻る。
