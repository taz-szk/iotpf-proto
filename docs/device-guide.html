1. Bootstrap / プロビジョニング

プラットフォーム管理者から受け取った Bootstrap Token を使い、 プラットフォームにデバイスを登録して証明書を取得します。 Bootstrap Token は 使い捨て（一度使うと無効化）です。

API 仕様

項目値
エンドポイントPOST {PLATFORM_URL}/api/provision
SSL 検証無効（CA 証明書取得前のためスキップ）
リクエスト Body{"bootstrap_token": "…", "device_id": "…"}
レスポンスcertificate, private_key, ca_certificate, tenant_id, device_id
⚠

Bootstrap フェーズは SSL ピア検証をスキップします。Bootstrap Token は使い捨てで短命なため、セキュリティリスクは限定的です。Bootstrap 完了後はすべての通信で証明書を使った mTLS が強制されます。

import os
from iot_platform import IotClient

client = IotClient(
    api_url="https://iot.suzuki-net.org/api",
    broker_host="iot.suzuki-net.org",
    broker_port=8883,
)

# BOOTSTRAP_TOKEN: 管理者から払い出されたトークン
# DEVICE_ID: このデバイス固有の識別子（例: シリアル番号）
client.provision(
    bootstrap_token=os.environ["BOOTSTRAP_TOKEN"],
    device_id="sensor-001",
    cert_dir="./certs",   # 証明書の保存先
    verify=True,           # 本番は True（Bootstrap のみ False 許容）
)
print("プロビジョニング完了 — certs/ に証明書を保存しました")
#include "iot_client.h"

int main(void) {
    const char *api_url = "https://iot.suzuki-net.org/api";
    const char *token   = getenv("BOOTSTRAP_TOKEN");
    const char *dev_id  = "sensor-001";
    const char *cert_dir = "./certs";

    iot_client_t *client = iot_client_create(api_url,
                               "iot.suzuki-net.org", 8883);
    if (!client) return 1;

    if (iot_provision(client, token, dev_id, cert_dir) != IOT_OK) {
        fprintf(stderr, "プロビジョニング失敗\n");
        iot_client_destroy(client);
        return 1;
    }
    printf("プロビジョニング完了 — %s に証明書を保存\n", cert_dir);
    iot_client_destroy(client);
    return 0;
}

2. 証明書の管理

プロビジョニング後、cert_dir に以下のファイルが作成されます。

ファイル内容用途
cert.pemデバイス証明書（公開鍵）MQTT mTLS クライアント認証
key.pemデバイス秘密鍵MQTT mTLS クライアント認証
ca.pemプラットフォーム CA 証明書サーバー証明書の検証
tenant_idテナント ID（テキスト）MQTT トピック・ClientID の構成
device_idデバイス ID（テキスト）MQTT トピック・ClientID の構成

証明書の有効期限

デフォルトの有効期間は 24 時間、最大 1 年（8760 時間）です。 有効期限が切れると MQTT 接続が拒否されます。更新には再度 Bootstrap Token が必要です。

✓

推奨: 証明書は不揮発ストレージ（フラッシュ / eMMC / セキュアエレメント）に保存してください。RAM に展開した後も秘密鍵（key.pem）はファイルアクセス権を 600 に設定するか、セキュアストレージに格納してください。

2 回目以降の起動（証明書の読み込み）

from iot_platform import IotClient

client = IotClient(
    api_url="https://iot.suzuki-net.org/api",
    broker_host="iot.suzuki-net.org",
    broker_port=8883,
)
# cert_dir に cert.pem / key.pem / ca.pem / tenant_id / device_id が存在すること
client.load_credentials("./certs")
# → これ以降 connect() を呼べる状態になる
iot_client_t *client = iot_client_create(
    "https://iot.suzuki-net.org/api",
    "iot.suzuki-net.org", 8883);

if (iot_load_credentials(client, "./certs") != IOT_OK) {
    fprintf(stderr, "証明書が見つかりません — Bootstrap が必要です\n");
    return 1;
}

3. MQTT 接続・mTLS 認証

接続パラメータ

パラメータ値
ブローカーホストiot.suzuki-net.org
ポート8883（MQTT over TLS）
TLS バージョンTLS 1.2 / TLS 1.3
クライアント認証mTLS（cert.pem + key.pem）必須
CA 証明書ca.pem（サーバー証明書の検証に使用）
Client ID{tenant_id}:{device_id}
Username{tenant_id}:{device_id}（password は空文字）
Keepalive60 秒
接続タイムアウト30 秒
 
client.load_credentials("./certs")

# connect() は内部で以下を行う:
#   1. client_id = "{tenant_id}:{device_id}" を設定
#   2. tls_set() で ca.pem / cert.pem / key.pem を渡す
#   3. ブローカーへ接続（タイムアウト 30s）
#   4. コマンドトピックを subscribe
#   5. status "online" を publish
client.connect()

# 切断時
client.disconnect()  # status "offline" を publish してから切断
/* iot_load_credentials() の後に呼ぶ */
if (iot_connect(client) != IOT_OK) {
    fprintf(stderr, "MQTT 接続失敗\n");
    return 1;
}

/* イベントループを回す (ブロッキング) */
while (running) {
    iot_loop(client, 1000);  /* タイムアウト ms */
}

iot_disconnect(client);
iot_client_destroy(client);
⚠

ca.pem はプラットフォーム独自の CA 証明書です。OS や言語のシステム証明書ストアには含まれていないため、必ず ca.pem を明示的に指定してください。指定しないとサーバー証明書の検証が失敗します。

4. 死活監視

プラットフォームはステータストピックへの publish でデバイスの死活を管理します。 connect() と disconnect() が自動で送信するため、 通常は明示的に呼び出す必要はありません。

タイミングトピックペイロード例
接続成功後/{tenant_id}/devices/{device_id}/status{"status":"online"}
切断前/{tenant_id}/devices/{device_id}/status{"status":"offline"}
FW バージョン付き同上{"status":"online","fw_version":"1.2.3"}

ファームウェアバージョンの報告

# 接続後に FW バージョンを付けて online を送信
client.publish_status("online", fw_version="1.2.3")
/* iot_connect() 後に呼ぶ */
iot_publish_status(client, "online", "1.2.3");
/* fw_version が不要な場合は NULL を渡す */
iot_publish_status(client, "online", NULL);

異常切断の検知

ネットワーク障害などで MQTT セッションが切れた場合、ブローカーは Last Will として {"status":"offline"} を自動送信します（MQTT 仕様の LWT 機能）。 アプリケーション側で再接続処理が必要です。 

import time

def on_disconnect():
    print("切断を検知 — 再接続を試みます")
    for delay in [5, 10, 30, 60]:
        time.sleep(delay)
        if client.force_connect():
            print("再接続成功")
            return
    print("再接続失敗")

client.set_disconnect_callback(on_disconnect)
/* paho mosquitto は on_disconnect コールバックで再接続を実装 */
static void on_disconnect(struct mosquitto *mosq,
                          void *obj, int rc) {
    if (rc != 0) {
        /* 予期しない切断: バックオフ後に再接続 */
        sleep(5);
        mosquitto_reconnect(mosq);
    }
}

5. テレメトリ送信

センサー計測値を JSON 形式で MQTT に publish します。 キー名は自由（プラットフォーム側でスキーマレスに受信）、値は数値または文字列を使用してください。

項目値
トピック/{tenant_id}/devices/{device_id}/telemetry
QoS1（at least once）
ペイロード形式JSON オブジェクト {"key": value, ...}
値の型数値（整数 / 浮動小数）または文字列
 
import time

client.connect()

while True:
    client.publish_telemetry({
        "temperature": 25.4,
        "humidity":    61.2,
        "pressure":    1013.5,
        "battery_mv":  3720,
    })
    time.sleep(30)  # 30 秒ごとに送信
while (running) {
    char payload[256];
    snprintf(payload, sizeof(payload),
        "{\"temperature\":%.1f,\"humidity\":%.1f,\"pressure\":%.1f}",
        read_temperature(),
        read_humidity(),
        read_pressure());

    iot_publish_telemetry(client, payload);

    iot_loop(client, 30000);  /* 30 秒待機しながらループ */
}
✓

送信間隔はデバイスのバッテリーと通信コストに合わせて調整してください。InfluxDB への書き込みは非同期で行われるため、高頻度送信も問題ありません（推奨: 1 秒〜数分間隔）。

6. コマンド受信

プラットフォームからデバイスへのコマンドは MQTT で配信されます。 connect() 時にコマンドトピックへの subscribe が自動で行われます。

項目値
トピック/{tenant_id}/devices/{device_id}/commands
QoS1
ペイロード形式{"type": "コマンド種別", ...}
コマンド種別"ota"（現在実装済み）
 
def on_command(cmd_type: str, payload: dict) -> None:
    if cmd_type == "ota":
        handle_ota(payload)
    else:
        print(f"未知のコマンド: {cmd_type}")

client.on_command(on_command)
client.connect()
client.loop_forever()  # ブロッキング待機

    } else {
        printf("未知のコマンド: %s\n", type);
    }
}

iot_set_command_callback(client, on_command, NULL);
iot_connect(client);

while (running) {
    iot_loop(client, 1000);
}

7. OTA アップデート

OTA コマンドを受信したら、指定 URL からファームウェアをダウンロードし、 SHA-256 チェックサムで整合性を検証します。検証が通った場合のみ適用してください。

OTA コマンドのペイロード

JSON — コマンドペイロード
{
  "type":         "ota",
  "version":      "2.0.0",
  "download_url": "https://iot.suzuki-net.org/api/firmware/download/abc123?X-Amz-Signature=...",
  "checksum":     "sha256:e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855"
}

OTA 処理の実装

from iot_platform import IotClient, OtaHandler
import sys

FIRMWARE_PATH = "/tmp/firmware.bin"

def on_command(cmd_type: str, payload: dict) -> None:
    if cmd_type != "ota":
        return

    print(f"OTA 受信: version={payload.get('version')}")

    # ダウンロード + SHA-256 検証（SDK が自動実行）
    success = OtaHandler.handle(payload, FIRMWARE_PATH)

    if success:
        print(f"検証 OK: {FIRMWARE_PATH}")
        # ここでプラットフォーム固有のフラッシュ書き込みを実装
        apply_firmware(FIRMWARE_PATH)
    else:
        print("ERROR: チェックサム不一致 — フォームウェアを破棄", file=sys.stderr)

#define FW_PATH "/tmp/firmware_update.bin"

static void on_command(const char *type, const char *json,
                       size_t json_len, void *user_data) {
    if (strcmp(type, "ota") != 0) return;

    /* download_url を JSON から抽出 */
    const char *url_key = "\"download_url\":\"";
    const char *p = strstr(json, url_key);
    if (!p) return;
    p += strlen(url_key);
    const char *end = strchr(p, '"');
    char url[512];
    size_t ulen = (size_t)(end - p);
    memcpy(url, p, ulen);
    url[ulen] = '\0';

    /* checksum を抽出 */
    char checksum[80] = "";
    const char *cs_key = "\"checksum\":\"";
    p = strstr(json, cs_key);
    if (p) {
        p += strlen(cs_key);
        end = strchr(p, '"');
        if (end) {
            size_t clen = (size_t)(end - p);
            if (clen < sizeof(checksum)) {
                memcpy(checksum, p, clen);
                checksum[clen] = '\0';
            }
        }
    }

    /* ダウンロード + SHA-256 検証 */
    int rc = iot_ota_download(url, FW_PATH, checksum);
    if (rc == IOT_OK) {
        printf("OTA 検証 OK: %s\n", FW_PATH);
        apply_firmware(FW_PATH);  /* プラットフォーム固有の実装 */
    } else {
        fprintf(stderr, "OTA 失敗 (rc=%d)\n", rc);
    }
}
⚠

チェックサム検証が失敗した場合は必ずフォームウェアを破棄し、現行バージョンで動作を継続してください。破損したファームウェアを適用するとデバイスが起動不能になります。

MQTT トピック一覧

トピック方向QoS説明
/{tenant_id}/devices/{device_id}/telemetry Device → Platform 1 センサー計測値。JSON オブジェクト形式
/{tenant_id}/devices/{device_id}/status Device → Platform 1 online / offline + オプションで fw_version

ℹ

tenant_id と device_id はプロビジョニング後に cert_dir/tenant_id と cert_dir/device_id ファイルに保存されます。SDK はこれらを自動で読み込んでトピックを構成します。

エラーコード（C SDK）

定数値説明
IOT_OK0成功
IOT_ERR_PROVISION-1プロビジョニング失敗（HTTP エラー / パース失敗 / ファイル書き込み失敗）
IOT_ERR_CONNECT-2MQTT ブローカーへの接続失敗
IOT_ERR_TLS-3TLS ハンドシェイク失敗（証明書不一致 / 期限切れ）
IOT_ERR_OTA-4OTA ダウンロード失敗またはチェックサム不一致
